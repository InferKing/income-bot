# План реализации MVP

## 1. Подход к поставке

Работа разбита на вертикальные инкременты. В конце каждого инкремента получается запускаемый и проверяемый результат. ML не начинается до появления надежного контура данных, портфеля, симулятора и baseline: иначе невозможно отличить качество модели от ошибок исполнения или данных.

## 2. Инкремент 0 — каркас проекта

### Работы

- инициализировать Git;
- создать `pyproject.toml` и `src`-layout;
- зафиксировать поддерживаемую версию Python 3.12;
- подключить Ruff, mypy и pytest;
- добавить `.env.example` и типизированную конфигурацию;
- добавить структурированное логирование;
- создать Dockerfile и `compose.yaml` с PostgreSQL;
- настроить SQLAlchemy и Alembic;
- добавить команды запуска процессов;
- создать CI для lint, types и tests.

### Результат

Приложение и PostgreSQL запускаются одной командой, миграции применяются автоматически или отдельной документированной командой, проверки воспроизводимы локально.

## 3. Инкремент 1 — Telegram и портфели

### Работы

- создать владельца при первичной инициализации;
- ограничить доступ по Telegram ID;
- реализовать главное меню;
- создать REAL_MANUAL и PAPER портфели;
- начислить виртуальному портфелю эквивалент 100 000 RUB;
- реализовать отдельные ручные операции;
- реализовать сверку полным снимком;
- реализовать расчет остатков и открытых позиций из ledger;
- добавить аудит исправлений;
- показать суммы в USDT и RUB.

### Тесты

- неизвестный Telegram ID не получает доступ;
- повтор одной команды не создает дубль операции;
- корректирующая запись сохраняет исходную историю;
- snapshot совпадает с replay журнала;
- REAL_MANUAL и PAPER не смешиваются.

### Результат

Бот уже полезен как ручной журнал портфеля, даже без торговых сигналов.

## 4. Инкремент 2 — рыночные данные

### Работы

- реализовать канонические инструменты;
- подключить Bybit REST для backfill свечей;
- подключить Bybit WebSocket для свечей, сделок и стакана;
- поддержать snapshot/delta и sequence стакана;
- получить derivatives metrics;
- реализовать проверку свежести и пропусков;
- реализовать backfill пропущенных свечей;
- подключить OKX как резервный адаптер;
- реализовать сравнение основных цен;
- подключить курс USDT/RUB;
- добавить health и уведомления об отказах.

### Тесты

- contract tests на сохраненных payload поставщиков;
- reconnect не теряет подписки;
- повторный REST backfill не создает дубли;
- нарушение sequence инвалидирует стакан до нового snapshot;
- stale data блокируется;
- Decimal и единицы нормализуются одинаково для обоих источников.

### Результат

Система круглосуточно собирает проверенные данные BTC/USDT, ETH/USDT и TON/USDT.

## 5. Инкремент 3 — риск и paper trading

### Работы

- реализовать модель заявки и исполнения;
- реализовать рыночное и лимитное виртуальное исполнение;
- учесть spread, комиссии, slippage и funding;
- реализовать позиции SPOT, LONG и SHORT;
- реализовать stop-loss и один take-profit;
- реализовать полный CLOSE;
- рассчитать PnL, margin и liquidation estimate;
- реализовать динамический размер позиции;
- реализовать автоматический выбор плеча 1x–20x;
- применить лимиты 10% / 1% / 5% / 15% / 3 позиции;
- реализовать дневную и drawdown-блокировки;
- построить equity curve и основные метрики.

### Инварианты

- доступный cash не становится отрицательным без явно разрешенного заемного механизма;
- закрытие не превышает открытую позицию;
- каждый fill отражен в ledger ровно один раз;
- риск-модуль проверяется перед каждым входом;
- spot и futures одного актива могут существовать одновременно;
- частичное закрытие не создается.

### Результат

Любую детерминированную стратегию можно честно прогнать в виртуальном портфеле.

## 6. Инкремент 4 — backtest и baseline

### Работы

- создать единый интерфейс стратегии для backtest и live paper;
- реализовать event-driven backtest;
- добавить хронологические splits и walk-forward;
- добавить baseline: buy-and-hold, moving-average trend и простую mean reversion;
- создать отчеты по доходности, drawdown, profit factor, expectancy, Sharpe и Sortino;
- добавить разрезы по активам, режимам и времени;
- проверить отсутствие look-ahead bias;
- обеспечить воспроизводимость запуска.

### Результат

Есть доверенный эталон, относительно которого можно оценивать ML.

## 7. Инкремент 5 — признаки и первая ML-модель

### Работы

- определить точные target для горизонтов 5m, 15m, 1h и 4h;
- построить feature pipeline;
- добавить технические, микроструктурные и деривативные признаки;
- определить режим рынка;
- обучить простые модели и градиентный бустинг;
- откалибровать вероятности;
- построить ансамбль;
- сформировать feature contributions;
- преобразовать прогнозы в BUY/LONG/SHORT/CLOSE/HOLD policy;
- применить порог 70%;
- проверить критерии допуска на невидимом периоде.

### Защита от переобучения

- feature selection выполняется только внутри train/validation;
- test-период не используется для подбора параметров;
- комиссии и slippage не оптимизируются задним числом на финальном test;
- сравнивается устойчивость по нескольким временным окнам;
- сохраняются dataset hash, code version и параметры.

### Результат

Первая версия модели либо объективно проходит критерии допуска, либо система остается на baseline без публикации слабой модели.

## 8. Инкремент 6 — сигналы и объяснения

### Работы

- реализовать signal policy;
- добавить дедупликацию и cooldown;
- рассчитывать срок действия и условие отмены;
- сформировать русскоязычное объяснение из вкладов признаков;
- добавить срочные предупреждения;
- реализовать transactional outbox;
- показать историю и причины блокировки;
- добавить паузу обычных сигналов.

### Результат

Владелец получает только актуальные, объяснимые и прошедшие риск-проверку уведомления.

## 9. Инкремент 7 — автоматическое переобучение

### Работы

- реализовать scheduler;
- добавить weekly training run;
- реализовать champion/challenger registry;
- автоматизировать проверку критериев;
- добавить атомарную активацию модели;
- добавить откат;
- уведомлять о результате обучения и деградации;
- показать активную версию и метрики в боте.

### Результат

Модель обновляется без ручного копирования файлов и не публикуется при ухудшении качества.

## 10. Инкремент 8 — production и paper-период

### Работы

- подготовить Linux VPS;

- добавить health checks и restart policy;
- настроить ежедневный backup и проверку восстановления;
- настроить ротацию логов и метрики;
- проверить восстановление после остановки процессов;
- запустить 30-дневный paper trading;
- зафиксировать изменения модели во время контрольного периода;
- сформировать итоговый отчет допуска.

### Результат

Система работает круглосуточно и собирает достаточные данные для решения о практической полезности сигналов.

## 11. Обязательные quality gates

Каждый pull request или локальный этап проходит:

```text
ruff check
ruff format --check
mypy
pytest
alembic upgrade head на пустой БД
alembic upgrade head на предыдущей версии БД
```

Для финансовой логики дополнительно используются property-based tests:

- сохранение балансов;
- отсутствие отрицательных количеств;
- симметрия LONG/SHORT там, где она ожидается;
- монотонность комиссий;
- соблюдение лимита позиции и стоп-риска;
- идемпотентность повторной обработки.

## 12. Порядок ближайшей реализации

Первый рабочий цикл должен включать только Инкременты 0 и 1:

1. Создать каркас и локальную инфраструктуру.
2. Поднять PostgreSQL и применить первую миграцию.
3. Запустить защищенного Telegram-бота.
4. Создать два портфеля и стартовый PAPER-баланс.
5. Реализовать ввод операции и отображение баланса.
6. Добавить сверку остатков.
7. Закрыть сценарии unit/integration-тестами.

После этого подключается Bybit. Такой порядок не блокирует работу отсутствующим внешним API и сразу проверяет наиболее чувствительную часть — корректность финансового ledger.

## 13. Предварительное определение готовности первой итерации

- `docker compose up` поднимает PostgreSQL и приложение;
- команда инициализации создает владельца и два портфеля;
- бот отвечает только разрешенному Telegram ID;
- владелец может добавить пополнение, вывод, покупку и продажу;
- владелец может сверить остатки полным снимком;
- отображаются реальные и виртуальные балансы в USDT/RUB;
- стартовый paper-капитал равен 100 000 RUB;
- повтор webhook/update не дублирует операцию;
- миграции и тесты проходят с чистого окружения;
- README содержит точные команды локального запуска.
